# 500 条 Benchmark 阶段性验证报告

## 1. 测试集

测试集共 500 条，全部由 GPT-5.6-sol 逐条编写，其中包含 250 条明确造型描述和 250 条模糊人物、场景或审美描述。本报告与 `benchmark_500/深思827结果报告.md` 使用同一批输入和人工 `expected`。

| 预期字段组合 | 数量 |
|---|---:|
| 无主节点预期 | 30 |
| 仅风格 | 80 |
| 仅车型 | 80 |
| 仅级别 | 40 |
| 风格 + 车型 | 100 |
| 风格 + 级别 | 50 |
| 车型 + 级别 | 50 |
| 风格 + 车型 + 级别 | 70 |

风格和车型各有 300 条非空预期，级别有 210 条；人工预期标签总数分别为 319、301 和 210。排除三个字段均为空的 30 条后，共有 470 条样本至少需要判断一个字段。

本报告统一采用参考报告中的评价标准：

- `Precision = 正确预测标签数 / 全部预测标签数`，空预期字段上返回的标签计为 false positive；
- `Recall = 正确预测标签数 / 全部预期标签数`；
- 只有与人工预期枚举名称完全一致的标签才计为 TP，不合并 SUV/MPV 尺寸类别，也不删除级别名称中的“级”字；
- 一个非空字段只要命中至少一个正确标签，就视为该字段命中；一条样本的所有非空必需字段均命中，才视为联合命中；
- 额外候选会降低 Precision，但不会取消已经命中的正确标签；
- 空预期字段不参与 Recall 和联合命中计算，其误推断情况单独统计。

## 2. 总体结果

### 2.1 标签级 Precision、Recall 和 F1

| 字段 | TP | 预测标签数 | 预期标签数 | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| 风格 | 284 | 774 | 319 | 36.7% | 89.0% | 52.0% |
| 车型 | 138 | 712 | 301 | 19.4% | 45.8% | 27.2% |
| 级别 | 0 | 4 | 210 | 0.0% | 0.0% | 0.0% |
| 微平均总体 | 422 | 1,490 | 830 | **28.3%** | **50.8%** | **36.4%** |

| 指标 | 结果 | 含义 |
|---|---:|---|
| 完成样例 | 500/500（100.0%） | 500 条均写入结果文件；其中包含无召回、无路径或调用失败后的空结果，不表示预测全部正确。 |
| 有风格或车型预期时，必需风格/车型联合命中 | 252/430（58.6%） | 430 条至少要求风格或车型；其中 252 条命中了该样本要求的全部非空风格、车型字段。级别不参与本行，额外候选不扣分。 |
| 所有必需字段联合命中 | 151/470（32.1%） | 470 条至少有一个非空预期字段；其中 151 条命中了该样本的全部非空预期字段。 |
| 澄清判断一致 | 327/500（65.4%） | 系统的 `need_user_confirmation` 与人工 `needs_clarification` 一致。 |

“所有必需字段联合命中”受级别结果明显拖累。当前最终文件只输出了 4 个级别标签，而且其名称均未与人工枚举完全一致，因此级别 TP 为 0。

### 2.2 Precision 偏低的主要原因

当前系统不会让召回节点直接收敛到唯一风格或车型。每个召回节点都可能沿图谱中的不同路径连接到多个风格和车型，样本级汇总后，预测阶段又会在风格和车型上各保留最多两个不同候选。因此，大量样本最终给出了两个风格或两个车型：

| 每条样本输出的候选数 | 风格样本数 | 车型样本数 |
|---:|---:|---:|
| 0 个 | 42 | 58 |
| 1 个 | 142 | 172 |
| 2 个 | 316 | 270 |

500 条样本最终共产生 774 个风格标签和 712 个车型标签，而人工预期分别只有 319 个和 301 个。只要两个候选中有一个正确，就能增加 TP 和 Recall；另一个无关候选仍会进入预测标签数，成为 false positive，进而显著拉低 Precision。

风格最能体现这一现象：284 个正确标签使 Recall 达到 89.0%，但 774 个预测标签把 Precision 拉低到 36.7%。因此，当前结果说明系统能够较高概率把正确风格放入候选集，但候选收敛能力不足。

车型还受到标签粒度不一致的影响。Benchmark 使用 `SUV`、`MPV` 等大类，而系统经常输出 `紧凑型SUV`、`中型MPV` 等细分类别；按照参考报告要求的标签名称直接比较，这些不计为 TP。因此车型的 Precision、Recall 分别只有 19.4% 和 45.8%。

### 2.3 级别在后处理阶段大量丢失

LLM 原始响应中有 188 条给出了级别，忽略“级”字后缀后，这 188 条均能与人工预期对应；但最终预测文件只保留 4 条级别，其中只有 1 条在删除“级”字后能够对应。原因是程序在 LLM 给出级别后，又调用图谱分布方法重新推断；如果图谱推断为空，原有 LLM 级别会被覆盖。

按照本报告的正式标准，`A级` 与预期 `A` 名称不同，因此仍不计为 TP。当前级别问题同时包含两部分：一是 184 条 LLM 结果被后处理清空，二是最终输出枚举与 Benchmark 枚举格式不一致。

### 2.4 空字段误推断

| 字段 | 空预期样本 | 空预期时返回非空候选 | 误推断率 |
|---|---:|---:|---:|
| 风格 | 200 | 168 | 84.0% |
| 车型 | 200 | 164 | 82.0% |
| 级别 | 290 | 0 | 0.0% |

30 条三个主节点均无预期的样本中，系统仅对 2 条保持风格、车型和级别全部为空，完整克制率为 **6.7%**。这说明当前主要风险不是级别乱猜，而是召回节点扩展出的多个路径候选容易把通用配置、人口属性或使用场景解释成具体风格和车型。

### 2.5 主流程运行数据

| 环节 | 成功样本 | 占 500 条比例 |
|---|---:|---:|
| 至少召回一个节点 | 474 | 94.8% |
| 生成图谱路径 | 468 | 93.6% |
| LLM 调用成功 | 468 | 93.6% |
| 同时有路径且 LLM 成功 | 462 | **92.4%** |

当前主要损失来自三处：26 条没有达到 0.60 召回阈值，6 条召回后没有形成路径，另有 6 条因网络连接异常导致 LLM 调用失败。总计生成 28,868 条路径，468 条有路径样本平均包含 61.7 条路径；LLM 调用成功率为 468/474（98.7%）。

## 3. 分组结果

### 3.1 明确描述与模糊描述

| 输入类型 | 风格命中 | 车型命中 | 级别命中 | 所有必需字段联合命中 |
|---|---:|---:|---:|---:|
| 明确描述 | 128/150（85.3%） | 76/150（50.7%） | 0/105（0.0%） | 75/235（31.9%） |
| 模糊描述 | 142/150（94.7%） | 62/150（41.3%） | 0/105（0.0%） | 76/235（32.3%） |

模糊描述的风格命中高于明确描述，但其车型命中更低。结合较高的空字段误推断率，这不应直接理解为模糊输入更可靠：系统对人物与场景描述更倾向于主动补全风格，既增加风格 TP，也增加额外候选和误推断。

### 3.2 预期字段组合

| 预期组合 | 数量 | 所有必需字段命中 | 命中率 |
|---|---:|---:|---:|
| 仅风格 | 80 | 71 | 88.8% |
| 仅车型 | 80 | 34 | 42.5% |
| 仅级别 | 40 | 0 | 0.0% |
| 风格 + 车型 | 100 | 46 | 46.0% |
| 风格 + 级别 | 50 | 0 | 0.0% |
| 车型 + 级别 | 50 | 0 | 0.0% |
| 风格 + 车型 + 级别 | 70 | 0 | 0.0% |

包含级别的四类样本当前均无法形成完整命中，直接原因是最终级别标签被大量清空且枚举格式不一致。车型相关组合还受到 Benchmark 粗粒度标签与系统细粒度输出不一致的影响。

## 4. Top 25 Schema 已覆盖 91.6% 的全部样本

Schema 覆盖只检查一条样本是否同时存在风格路径和车型路径，不使用 `expected`，因此它评价的是路径模板覆盖能力，不是预测准确率。

| Schema 数量 N | 旧方法覆盖率 | 新方法覆盖率 |
|---:|---:|---:|
| 3 | 63.6% | 64.2% |
| 5 | 63.8% | 74.6% |
| 10 | 78.2% | 85.6% |
| 15 | 78.8% | 88.6% |
| 20 | 82.6% | 90.6% |
| 25 | 83.4% | **91.6%** |
| 30 | 84.8% | 92.0% |
| 50 | 88.6% | 92.2% |

新方法不再只选择出现次数最多的 Schema，而是优先选择能够补充新样本覆盖的 Schema。Top 25 由 9 个风格 Schema 和 16 个车型 Schema 组成，共覆盖 458 条；增加到 50 个 Schema 也只多覆盖 3 条。

**结论：** N=25 是当前较合适的规模，继续增加 Schema 的收益已经很小。后续应固定这 25 个 Schema，在独立数据上验证泛化覆盖能力。

## 5. 代表案例

### 5.1 有效结果

- `M031`：输入“贯穿式像素灯带、动态迎宾灯语、电子外后视镜”，预期风格为科技；系统返回科技和豪华，其中科技为正确标签，风格字段命中。
- `M124`：输入“后风挡固定不随箱盖开启、单独后备厢盖、四门五座”，预期车型为三厢轿车；系统返回三厢轿车，车型判断正确。
- `M241`：输入“两门双座、长机盖短尾、前保险杠导流槽、后扩散器”，预期为运动风格和跑车；系统同时命中风格与车型。

### 5.2 候选过多

- `M031` 虽然命中了科技，但同时返回豪华；车型在没有人工预期的情况下还返回中型 MPV 和中型 SUV。正确标签增加 TP，其余标签则增加 false positive。
- `M235` 预期为科技和三厢轿车，系统命中了这两项，但还返回豪华和中大型车。该样本可以通过必需字段联合命中，却仍会拉低 Precision。

这类结果是当前 Precision 偏低的典型来源：召回节点可以连接到多个风格和车型路径，预测端又保留 top-2，导致正确候选和弱相关候选一起输出。

### 5.3 车型粒度或方向不一致

- `M112`：六座、第二排通道、第三排可收折，人工预期为 `MPV`；系统返回 `中型MPV` 和 `紧凑型MPV`。语义方向正确，但按照参考报告的枚举名称直接比较，不计为 TP。
- `M138`：双排座舱和开放式货台，预期为皮卡；系统只返回商务风格，车型为空。
- `M163`：明确要求座舱与行李舱隔离、只开启箱盖，预期为三厢轿车；系统返回中型 MPV 和中大型 MPV，说明弱相关图谱路径压过了用户的直接车身结构描述。

### 5.4 级别被后处理清空

- `M453`：输入中明确写有“A0 级三厢轿车”，系统的 LLM 推理也识别出 A0，但最终预测文件中的 `car_level` 为 `null`。该案例直接体现了级别在后处理阶段被覆盖的问题。

### 5.5 空预期仍返回候选

- `M018`：“年轻人的第一辆车、预算有限”，三个主节点均无预期，但系统返回简约、科技和微型车。
- `M019`：“五十岁用户、上下班使用”，三个主节点均无预期，但系统返回豪华、科技、中型 SUV 和中型 MPV。
- `M023`：“国内城市使用、一年一万公里”，三个主节点均无预期，但系统返回科技、简约、小型车和微型车。

这些案例说明，人口属性、预算和一般使用场景会通过多跳关系扩展成具体风格与车型，而当前候选筛选不足以稳定拒绝这类弱推断。

## 6. 总结

本次 500 条 Benchmark 已完整生成结果，召回、路径查询和 LLM 预测的主流程基本跑通：474 条样本成功召回，468 条获得图谱路径，同时有路径且 LLM 调用成功的样本为 462 条，完整链路覆盖率为 **92.4%**。这说明系统已经具备大批量运行能力，当前重点已由“链路能否执行”转向“输出是否准确、是否克制”。

按照参考报告统一的标签级评价标准，系统微平均 Precision 为 **28.3%**、Recall 为 **50.8%**、F1 为 **36.4%**。风格 Recall 达到 89.0%，说明正确风格通常能够进入候选集；但每个召回节点都可能扩展出多条风格、车型路径，系统在样本级汇总时又允许每个字段保留最多两个不同候选，导致预测标签数远大于人工预期标签数。风格产生 774 个预测标签、车型产生 712 个，而对应预期分别只有 319 个和 301 个，因此额外候选显著拉低 Precision。

车型除候选过多外，还存在枚举粒度不一致：Benchmark 使用 SUV、MPV 大类，系统输出紧凑型 SUV、中型 MPV 等细类，按照当前标准不计为同一标签。级别则主要是后处理问题，LLM 原始响应中的 188 条有效级别最终只保留 4 条，同时还存在 `A` 与 `A级` 的格式差异。空字段误推断也较严重：风格和车型的误推断率分别为 84.0% 和 82.0%，30 条无主节点预期样本中只有 2 条完全保持空输出。

Top 25 Schema 已经覆盖 458/500 条样本，覆盖率为 **91.6%**，说明有限数量的高价值路径模板可以覆盖当前绝大多数风格、车型证据。下一阶段建议优先完成以下工作：

1. **减少额外候选。** 调整 top-2 保留条件，引入候选分差、最低置信度和弱路径过滤；证据明确时只输出 top-1，证据冲突时再保留两个候选并要求用户确认。
2. **统一车型枚举。** 明确系统最终输出采用 SUV/MPV 大类还是尺寸细类，并与 Benchmark 使用同一套词表后重新评测。
3. **修复级别链路。** 保留 LLM 已识别的有效级别，避免被空的图谱推断覆盖，同时统一 `A`、`A级` 等输出格式。
4. **提高拒答能力。** 对人口属性、预算、一般使用场景和局部配置设置更严格的证据门槛，减少空预期样本上的风格和车型误推断。
5. **补充运行稳定性。** 对 6 条网络失败增加有限重试，并用独立样本继续验证 Top 25 Schema 的泛化能力。
