# 路径 Schema 方向与 Top-N 覆盖率验证说明

## 一、结论摘要

本次验证针对 100 条 Benchmark 样本完成了两项检查：

1. 已将路径按“召回节点在前、风格/车型候选在后”的顺序展示。反转后的路径端点没有发散到大量候选：全部 100 条样本的风格端点不超过 2 个，车型端点也不超过 2 个。
2. 在能够到达汽车风格或汽车车型的 schema 中暂选 25 条，并将选取目标由“仅按频次排序”调整为“优先增加同时命中风格和车型的样本数”。新方法选出 12 条风格类 schema 和 13 条车型类 schema，共有 72 条样本同时命中两类，全链路通过率为 **72%**；相较直接截取频次前 25 条的 **62%**，提升 **10 个百分点**。进一步分阶段观察，100 条样本中只有 77 条成功召回且形成了 path，其中 72 条同时具备风格和车型路径证据；新方法覆盖了这 72 条全部可通过样本，相当于覆盖路径有效样本的 **93.5%（72/77）**，并达到当前双端点证据下的 **100% 可达上限（72/72）**。

需要特别说明：正式的端到端指标仍以全部 100 条 Benchmark 样本为分母，因此报告结果仍记为 72%。93.5% 和 100% 用于解释 schema 选择阶段在上游已产生有效路径数据后的表现，不能替代全链路通过率。当前第二项指标衡量的是风格、车型双端点联合覆盖率，并不是“每条样本都能同时到达车型和级别”；汽车级别尚未纳入该指标。同时，本次 schema 选择和通过率计算使用同一批 100 条样本，因此仍需使用独立样本验证稳定性。

## 二、疑问一：路径方向及候选是否发散

### 2.1 路径方向调整

原路径示例：

```text
简约 -> StyleAssociatedWith -> Friendly Compact Stance
```

调整后：

```text
Friendly Compact Stance <- StyleAssociatedWith <- 简约
```

调整只改变路径的展示顺序和箭头方向，不改变节点、关系及其图谱语义。反转后左侧为关键词召回命中的图谱节点，右侧为能够关联到的汽车风格或汽车车型，符合“从输入证据查看候选输出”的分析顺序。

该调整解决的是“路径展示倒置”问题。它证明某个召回节点能够通过哪些关系到达候选，并不表示知识图谱中只有这一条正确路径。

### 2.2 候选端点收敛验证

对 `benchmark_predict_reversed_paths.json` 中每条样本的全部路径进行统计：

- 路径以 `StyleAssociatedWith` 结束时，统计右侧不同汽车风格的数量；
- 路径以 `TypeAssociatedWith` 结束时，统计右侧不同汽车车型的数量；
- 同一样本、同一名称重复出现时只计 1 个候选。

统计结果如下：

| 指标 | 结果 |
|---|---:|
| Benchmark 样本数 | 100 |
| 风格端点为 0 个 | 25 |
| 风格端点为 1 个 | 1 |
| 风格端点为 2 个 | 74 |
| 风格端点超过 2 个 | 0 |
| 车型端点为 0 个 | 28 |
| 车型端点为 1 个 | 1 |
| 车型端点为 2 个 | 71 |
| 车型端点超过 2 个 | 0 |
| 风格、车型端点均不超过 2 个 | 100/100（100%） |

由此可见，召回节点对应的路径候选会集中在 1～2 个汽车风格和 1～2 个汽车车型，并未出现大量风格或车型端点同时发散的情况。端点为 0 表示该样本在相应维度没有形成可用候选，应理解为证据不足，而不是形成了更多候选。

该指标验证的是“候选数量是否收敛”，不直接等同于候选语义是否正确；候选正确性仍需结合人工标注或目标答案另行评估。

## 三、疑问二：Top-N Schema 统计与通过率

### 3.1 验证口径：必须同时命中风格和车型

当前代码按以下步骤准备候选 schema：

1. 将每条具体路径抽象为节点类型和关系类型组成的 schema；
2. 将 schema 反转，使召回节点类型位于左侧，汽车风格或汽车车型位于右侧；
3. 只保留最终能够关联到“汽车风格”或“汽车车型”的 schema；
4. 统计每条 schema 分别出现在哪些 Benchmark 样本中；
5. 从候选集合中暂选 25 条 schema；
6. 对每条样本检查是否同时命中至少 1 条风格类 schema 和至少 1 条车型类 schema。

由于每条样本内部的 `hit_path_schemas` 已经去重，因此 schema 的 `count` 表示“覆盖了多少条不同样本”，而不是同一路径在一条样本中重复出现的次数。

设选中的 schema 集合为 `A`。其中，风格类 schema 覆盖样本的并集记为 `StyleCover(A)`，车型类 schema 覆盖样本的并集记为 `TypeCover(A)`，则通过样本集合为：

```text
Pass(A) = StyleCover(A) ∩ TypeCover(A)
```

总体通过率为：

```text
pass_rate = |Pass(A)| / 100
```

因此，“命中任意一条 schema”不足以判定通过；同一条样本必须同时具有风格路径证据和车型路径证据。

### 3.2 Schema 选取方法：优先增加新增通过样本

仅按频次直接截取前 25 条 schema，没有考虑风格类和车型类 schema 是否能在同一批样本上形成配对。为使选取目标与通过率定义一致，当前采用确定性的贪心选取方法：

1. 初始时风格覆盖集合、车型覆盖集合和通过集合均为空；
2. 对每一条尚未选择的候选 schema，模拟将其加入当前集合；
3. 计算该候选能新增多少条“风格和车型同时命中”的样本；
4. 选择新增通过样本数最多的一条；
5. 若新增通过数相同，则依次优先选择：同类别新增覆盖更多、总体覆盖频次更高、原始排名更靠前的 schema；
6. 更新覆盖集合并重复上述步骤，直到选满 25 条。

候选 schema `s` 的首要评分为：

```text
Δpass(s) = |Pass(A ∪ {s}) - Pass(A)|
```

完整排序依据为：

```text
(新增通过样本数, 同类别新增覆盖数, schema覆盖样本数, 原始排名)
```

这一方法允许风格类 schema 与车型类 schema 覆盖相同样本。此类跨类别重叠能够让样本同时形成风格和车型证据，是有效覆盖；不再将其作为普通重复直接过滤。同类别 schema 的重复覆盖则只有在还能增加联合通过数或补充新覆盖时才有选择价值。

该方法属于贪心算法：每一步选择当前收益最大的一条 schema，计算量较小、选择过程可复现，但不声称得到所有 25 条组合中的数学全局最优解。

### 3.3 Top-25 结果：通过率由 62% 提升至 72%

当前暂取 `N=25`，结果如下：

| 指标 | 直接按频次取前 25 条 | 通过率导向选取 25 条 |
|---|---:|---:|
| 风格类 schema 数量 | 15 | 12 |
| 车型类 schema 数量 | 10 | 13 |
| 命中至少 1 条风格类 schema 的样本数 | 67 | 75 |
| 命中至少 1 条车型类 schema 的样本数 | 62 | 72 |
| 同时命中风格类和车型类的样本数 | 62 | 72 |
| 通过率 | 62% | **72%** |

在 schema 总量仍为 25 条的前提下，新方法新增 10 条通过样本，通过率提升 10 个百分点。最终选出的 12 条风格类 schema 和 13 条车型类 schema，不是预先规定的固定配额，而是算法根据每一步对联合通过率的增益自动形成的结果。

72% 还需要结合上游有效数据范围理解。当前 100 条样本的阶段分布如下：

| 观察口径 | 样本数 | 新方法通过数 | 阶段内覆盖率 |
|---|---:|---:|---:|
| 全部 Benchmark 样本 | 100 | 72 | **72.0%** |
| 成功召回且形成 path 的样本 | 77 | 72 | **93.5%** |
| 同时具备风格和车型路径证据的样本 | 72 | 72 | **100%** |

因此，未通过的 28 条样本不能全部归因于 Top-N schema 选择：其中 23 条没有形成 path，另有 5 条虽存在 path，但没有同时形成风格和车型两类证据。在当前路径结果中，只有 72 条样本具备满足通过条件的基础证据，而新方法已将这 72 条全部覆盖。由此看，**72% 的全链路通过率在当前召回与路径产出的约束下已达到可观测上限，schema 选择阶段的结果是较优的**；若要继续提高全链路通过率，重点应转向召回覆盖和路径构建，而不是继续单纯扩大 Top-N。

### 3.4 不同 N 下的新旧方法对比

下表使用同一批 100 条 Benchmark 样本和同一通过条件进行比较。老方法表示“按覆盖频次直接取前 N 条”，新方法表示“优先选择能够新增风格、车型联合通过样本的 schema”。

| N | 老方法通过数 | 老方法通过率 | 新方法通过数 | 新方法通过率 | 提升 |
|---:|---:|---:|---:|---:|---:|
| 3 | 51 | 51% | 51 | 51% | 0 个百分点 |
| 5 | 51 | 51% | 58 | 58% | +7 个百分点 |
| 10 | 59 | 59% | 64 | 64% | +5 个百分点 |
| 15 | 60 | 60% | 67 | 67% | +7 个百分点 |
| 20 | 61 | 61% | 70 | 70% | +9 个百分点 |
| 25 | 62 | 62% | 72 | **72%** | **+10 个百分点** |
| 30 | 62 | 62% | 72 | 72% | +10 个百分点 |
| 50 | 64 | 64% | 72 | 72% | +8 个百分点 |

结果表明：当 `N=3` 时可选空间较小，两种方法结果相同；从 `N=5` 开始，新方法持续优于直接频次排序，并在 `N=25` 时覆盖当前全部 72 条双端点可达样本。继续将 N 增加到 30 或 50 不再提高通过率，只会增加 schema 数量和解释成本，因此当前采用 `N=25` 具有明确依据。

### 3.5 结果解释边界

- **当前验证端点是汽车风格和汽车车型。** 汽车级别尚未进入 schema 候选和通过条件，因此本结果不能表述为“车型和级别通过率”。
- **72% 是样本内覆盖结果。** 这 100 条 Benchmark 样本同时参与了 schema 选择和通过率计算，说明该方法能够更好地覆盖当前样本，但不能单独证明对新样本也能达到 72%。
- **通过不等于语义正确。** 当前指标只检查是否存在可达的风格类和车型类 schema，没有将路径终点与人工标注答案逐条比较。
- **N=25 仍是暂定值。** 当前结果证明在相同 N 下，联合通过率导向的选取优于直接按频次截取；最终 N 仍应结合解释成本、目标通过率和独立验证结果确定。

## 四、后续验证建议

1. 固定当前选出的 25 条 schema，在未参与选择的独立样本上重新计算通过率，用于验证稳定性；
2. 如果交付目标确实要求“车型和级别”，需先补充能够到达汽车级别的 schema，再将通过条件调整为相应的双端点或多端点条件；
3. 对入选的 25 条 schema 做人工语义抽查，确认高覆盖路径不仅可达，而且符合业务含义；
4. 在独立验证集上比较不同 N 的通过率和人工正确率，再确定最终 N。
